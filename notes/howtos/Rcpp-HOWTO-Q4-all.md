# A:4.1.2 (Claude) {#QA4.1.2-claude}
> Resolving Persistent RcppEigen Include in RcppExports.cpp

The issue you're experiencing is that `Rcpp::compileAttributes()` is
still generating `#include <RcppEigen.h>` in `RcppExports.cpp` despite
your code refactoring. This occurs due to `compileAttributes()`
scanning the **entire package configuration**, not just individual
source files.

## Root Cause Analysis

### 1. DESCRIPTION File Triggers Automatic Inclusion

The primary culprit is your `DESCRIPTION` file:

```yaml
LinkingTo: Rcpp, RcppArmadillo, RcppEigen, RcppGSL
```

`Rcpp::compileAttributes()` **automatically includes headers** for ALL packages listed in `LinkingTo`, regardless of whether they're actually used in exported functions[^1]. This is a design decision to ensure all linked libraries are available in the generated exports file.

### 2. Algorithm Behind Include Generation

```cpp
// Simplified compileAttributes() logic
std::vector<std::string> linkingTo = readLinkingToField(DESCRIPTION);
for (const auto& pkg : linkingTo) {
    if (pkg == "RcppArmadillo") includes.push_back("<RcppArmadillo.h>");
    if (pkg == "RcppEigen") includes.push_back("<RcppEigen.h>");
    if (pkg == "RcppGSL") includes.push_back("<RcppGSL.h>");
    // ... etc
}
```

## Complete Solution: Selective Linking Strategy

Here's a comprehensive approach to eliminate the unwanted `RcppEigen.h` inclusion:

### Option 1: Remove RcppEigen from LinkingTo (Recommended)

#### Modified DESCRIPTION
```yaml
Depends:

    Rcpp,

    RcppGSL,
    argparse
```

# A:4.1.2 (Kimi)
> ...

Why does `RcppExports.cpp` still contain

```cpp
#include <RcppArmadillo.h>
#include <RcppEigen.h>
```

even though you removed every `// [[Rcpp::depends(*)]]` tag and
isolated the Eigen code?

Because **Rcpp reads the package’s *LinkingTo* field**, not the `//
[[Rcpp::depends()]]` attributes, when it decides which headers must be
available in the *single* translation unit that is `RcppExports.cpp`.

As long as a package name appears in `LinkingTo:`,
`compileAttributes()` adds the corresponding header to the generated
preamble – **in alphabetical order** – so

```
LinkingTo: RcppArmadillo, RcppEigen
```

inevitably yields

```cpp
#include <RcppArmadillo.h>
#include <RcppEigen.h>
```

and the clash is back.

Therefore the cure is:

1. Remove **RcppEigen** from `LinkingTo` (keep it in `Suggests` so that
   `install.packages()` still knows the dependency).
2. Supply the required compiler / linker flags yourself.

Below is a minimal patch set that keeps Eigen completely private and
eliminates the unwanted include.

--------------------------------------------------
1.  DESCRIPTION

```yaml
LinkingTo: Rcpp, RcppArmadillo, RcppGSL   # <- RcppEigen removed
Suggests: RcppEigen                       # still shipped with the package
```

--------------------------------------------------
2.  src/Makevars

Add the Eigen headers to `PKG_CPPFLAGS` manually and keep the warning
switch.

```make
EIGEN_CPPFLAGS = -I$(R_PACKAGE_DIR)/RcppEigen/include \
                 -DEIGEN_PERMANENTLY_DISABLE_STUPID_WARNINGS

PKG_CPPFLAGS  = -I../inst/include -DSTRICT_R_HEADERS $(EIGEN_CPPFLAGS)
PKG_CXXFLAGS  = $(SHLIB_OPENMP_CXXFLAGS) $(GSL_CFLAGS)
PKG_LIBS      = $(SHLIB_OPENMP_CXXFLAGS) $(LAPACK_LIBS) $(BLAS_LIBS) \
                $(FLIBS) $(GSL_LIBS)
```

`R_PACKAGE_DIR` expands to the library tree of the current package
(e.g. `$R_LIBS_USER/dvesimpler`), so the headers are found even though
the package is *not* in `LinkingTo`.

Key takeaway
------------

`compileAttributes()` honours **only** `LinkingTo` when it builds the
unified header list.
To keep a library private, drop it from `LinkingTo`, add the
necessary `-I` flags in `Makevars`, and isolate the corresponding
`#include` inside a single `.cc` / `.cpp` file that is **not** scanned
by `compileAttributes()`.

```cpp
NumericMatrix outer_omp_simd(NumericVector x, NumericVector y) {
  const R_xlen_t n = x.size();
  const R_xlen_t m = y.size();
  NumericMatrix out(n, m);

  const double* RESTRICT px = REAL(x);
  const double* RESTRICT py = REAL(y);
  double* RESTRICT pout = REAL(out);

  // Parallelize rows; SIMD within the inner loop
  #ifdef _OPENMP
  #pragma omp parallel for schedule(static)
  #endif
  for (R_xlen_t i = 0; i < n; ++i) {
    const double xi = px[i];

    #if defined(__GNUC__) || defined(__clang__)
    #pragma omp simd
    #endif
```

```cpp
Rcpp::NumericMatrix outer_product_rcpp(Rcpp::NumericVector v1, Rcpp::NumericVector v2) {

}
```
