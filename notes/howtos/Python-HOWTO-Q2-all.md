## Questions

### Where to place Python related files in a R CRAN compliant project?

The correct, CRAN-compliant location for your entire Python package
source code is within the `inst/` directory of your R package.

A common and recommended convention is to place it in a subdirectory
named `inst/python/`.

-----

### 📁 The Correct Location: `inst/python/`

The `inst/` directory is the standard place for arbitrary files that
need to be included in the final *installed* R package. When your R
package is installed, everything inside `inst/` is copied to the top
level of the installation directory.

By placing your Python project in `inst/python/`, your R package code
can reliably find it after installation using `system.file()`.

Your project structure would look like this:

```
myRPackage/
├── R/
│   └── wrappers.R
├── man/
│   └── wrappers.Rd
├── inst/
│   └── python/
│       └── my_python_project/    <-- Your entire Python project
│           ├── my_python_pkg/    <-- The Python source module
│           │   ├── __init__.py
│           │   └── core.py
│           ├── pyproject.toml
│           └── poetry.lock       (or other relevant files)
├── DESCRIPTION
├── NAMESPACE
└── ...
```

-----

### 🐍 Integrating with `reticulate` (CRAN-Safe)

You are correct to use `virtualenv` and `poetry`. The key challenge for CRAN is that **you cannot run `poetry install` or access the internet during CRAN checks.**

The installation of the Python environment and its dependencies *must* happen on the **user's machine** after they install your R package.

The best practice is to **not** try to install this automatically in `.onLoad()`. Instead, provide an exported helper function that the user runs once to set up the Python environment.

Here is the recommended, CRAN-safe workflow:

#### 1\. Add `reticulate` to `DESCRIPTION`

Your `DESCRIPTION` file must list `reticulate`.

```
Imports:
    reticulate
Suggests:
    python (>= 3.8)
```

#### 2\. Use `delay_load` in your R code

In your R code (e.g., in `R/zzz.R`), you can define a placeholder for your Python module using `reticulate::import(..., delay_load = TRUE)`. This prevents R from trying to load Python immediately when the package is loaded, which would fail if the environment isn't set up.

```r
# In R/zzz.R or a similar file
.py_pkg <- NULL

.onLoad <- function(libname, pkgname) {
  .py_pkg <<- reticulate::import("my_python_pkg",
                                 delay_load = list(
                                   on_load = function() {
                                     # Optional: message to user on successful load
                                   },
                                   on_error = function(e) {
                                     warning(paste(
                                       "Python package 'my_python_pkg' not found.",
                                       "Please run 'install_my_python_env()' to set it up."
                                     ), call. = FALSE)
                                   }
                                 ))
}
```

#### 3\. Create an Exported Install Function

This is the most important step. Create an R function (e.g., `install_my_python_env()`) that the user will call. This function finds your bundled Python code, creates a dedicated virtual environment, and runs the installation.

```r
#' Install Python Dependencies
#'
#' Creates a dedicated Python virtual environment for the package
#' and installs the required Python dependencies using poetry.
#'
#' @export
install_my_python_env <- function() {
  
  # 1. Find the path to your bundled Python project
  # This path is *inside* the installed R package
  py_proj_dir <- system.file("python/my_python_project", package = "myRPackage")
  
  if (py_proj_dir == "") {
    stop("Could not find bundled Python project. Please reinstall 'myRPackage'.")
  }
  
  # 2. Define a dedicated virtual environment name
  env_name <- "myRPackage-env"
  
  # 3. Create the virtual environment if it doesn't exist
  if (!reticulate::virtualenv_exists(env_name)) {
    cat("Creating virtual environment '", env_name, "'...\n")
    reticulate::virtualenv_create(env_name)
  } else {
    cat("Virtual environment '", env_name, "' already exists.\n")
  }
  
  # 4. Use py_install to install the package from the local source directory
  # pip is able to install from a directory containing pyproject.toml
  # This will also install all dependencies defined in the toml file.
  cat("Installing Python package 'my_python_project' and its dependencies...\n")
  reticulate::py_install(
    packages = py_proj_dir,      # Path to your Python project
    envname = env_name,
    pip = TRUE                   # Use pip for installation
  )
  
  cat(paste(
    "Installation complete! Please restart your R session and run",
    "'library(myRPackage)' to use the Python-backed features.\n"
  ))
}
```

#### 4\. Instruct the User

In your package's `README.md` and function documentation, you must instruct the user to run `install_my_python_env()` once after installing the R package.

-----

### 📦 Summary: Key CRAN Compliance Points

  * **Location:** `inst/python/`
  * **Installation:** Must be **user-initiated** via an exported R function (like `install_my_python_env()`).
  * **No Network in Checks:** Your package must load and pass checks *without* the Python environment being present. Using `reticulate::import(..., delay_load = TRUE)` is essential for this.
  * **Documentation:** Clearly document the one-time setup step for your users in the `README` and package vignettes.
